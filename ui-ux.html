How we use these

  • Prefer semantic HTML and native controls before adding a library.
  • Choose components with documented keyboard and screen-reader behaviour.
  • GoldBrief Build 1 ships no UI framework dependency; these are references for patterns such as focus management, tokens and responsive layout.
  • Record the license before copying any code.

Building a new component with AI

AI can draft a component quickly. The quality comes from the brief you give it and the review you do afterward.

  1. Define the job first. Write one sentence on what the component is for and who uses it. List every state it needs: default, hover, focus, disabled, loading, empty and error.
  2. Give it your constraints. Paste your design tokens (colors, spacing, type), name the framework, and require keyboard operation, visible focus and WCAG 2.2 AA contrast. Say whether new dependencies are allowed.
  3. Start from accessible primitives. Ask it to compose a headless or accessible base (for example Base UI, Radix, Reka UI or Zag from the list above) instead of re-inventing focus handling, ARIA roles and keyboard patterns.
  4. Ask for the API before the code. Request the props, usage examples and edge cases first. Agree on the interface, then ask for the implementation, one component per prompt.
  5. Review it like a stranger's pull request. Read the code. Operate it with the keyboard only, check it with a screen reader, resize from 320 to 1920 px, and test reduced motion and high contrast. AI can invent props, libraries or ARIA attributes that do not exist.
  6. Test with real content. Try long words, translated text, empty data, large type and right-to-left text. Add automated tests: unit, visual regression and an accessibility checker such as axe.
  7. Check licenses and provenance. Generated code can resemble licensed code. Prefer original output, run a license or similarity check where you can, and record where the component came from.

Prompt template

Build a <Component> in <framework>.
Purpose: <one sentence>. Users: <who>.
States: default, hover, focus-visible, disabled, loading, error.
Constraints: use only these design tokens: <paste>. No new dependencies. Keyboard operable, visible focus, WCAG 2.2 AA contrast, works from 320 to 1920 px, respects prefers-reduced-motion.
Base it on: <headless primitive or an existing component>.
Return, in order: the props API, a usage example, the implementation, then a manual test checklist.

How AI can improve interface design

Used well, AI widens the options you consider and catches problems earlier. People still decide what is good.

Explore more options

Generate several layouts or variants of one screen to compare. The value is in the comparison, not in accepting the first output.

Review accessibility

Ask for a review of heading order, labels, link text, alt text and color contrast, alongside automated checkers. It finds issues faster but does not replace testing with assistive technology and real users.

Write clearer interface text

Rewrite error messages, empty states and button labels in plain language, then test them with real readers.

Keep a design system consistent

Have AI flag spacing, color and type that drift from your tokens, and propose fixes through a normal reviewed change.

Make adaptation easier

Support translation, reading level, text size and density settings so more people can use the same interface.

Speed up research synthesis

Summarize interview notes or feedback into themes, then check each theme against the original quotes.

Find layout bugs earlier

Generate unusual test content and run automated checks for overflow and broken navigation across screen sizes, as GoldBrief's daily review does.

Watch out for

  • Output tends toward the generic. Brief it with your brand and real content.
  • It can state wrong things about browser support, APIs and accessibility rules. Verify against the specification.
  • Do not paste private user data, unreleased designs or credentials into tools you have not reviewed.
  • Automated or AI review is a first pass. A person should approve visual changes before they ship.
